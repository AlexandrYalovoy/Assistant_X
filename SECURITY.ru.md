# Политика безопасности

## Поддерживаемые версии

| Версия | Поддерживается |
| --- | --- |
| 0.5.4 (текущая) | да |

Исправления безопасности получает только последняя выпущенная версия. Assistant X — прототип: исправление выходит в
новой версии, а не в виде заплатки к старой.

## Как сообщить об уязвимости

Пожалуйста, сообщайте об уязвимости **конфиденциально**, а не в открытом issue:

- на GitHub — вкладка **Security** репозитория проекта (https://github.com/AlexandrYalovoy/Assistant_X/security) →
  **Report a vulnerability** (закрытое сообщение о безопасности, которое видит только сопровождающий).
- Адрес электронной почты не публикуется. Если вы не можете воспользоваться этой формой, откройте на GitHub issue с
  заголовком **private contact request** без каких-либо подробностей уязвимости; автор ответит там и предложит закрытый
  канал связи. Пользователи зеркала на GitFlic идут тем же путём через GitHub: у зеркала нет собственной формы для таких
  сообщений.

Опишите, что может сделать злоумышленник, укажите версию и шаги или файл, который это демонстрирует (специально
подготовленный базовый пакет, документ, команда). Пожалуйста, не прикладывайте документы с личным или конфиденциальным
содержанием.

Чего ожидать:

- подтверждение получения в течение **7 дней**;
- оценку (принято или нет и степень серьёзности) в течение **30 дней**;
- исправление в новой версии, как только оно будет готово, — для принятого сообщения обычно в течение **90 дней**;
  сообщение о безопасности публикуется вместе с исправлением с указанием автора находки, если он не попросит иначе.

## Модель доверия

Assistant X работает на собственном ПК пользователя и для этого пользователя. Он читает файлы, которые пользователь не
писал сам: документы любых форматов, архивы в папке inbox, базовые пакеты, полученные от других людей. Всё это
считается **недоверенными данными**.

### Что гарантирует продукт

- **Базовые пакеты** (`.axbase`, [docs/PACKAGES.md](docs/PACKAGES.ru.md), раздел «Доверие»): прежде чем что-либо
  изменится, проверяется каждая строка манифеста (id, версия, профиль, языки карточек…), каждое имя элемента (никаких
  `..`, абсолютных путей, дисков, двоеточий, ссылок, имён устройств), каждый файл — по контрольной сумме, каждая
  карточка — по схеме; каждый путь, указанный в карточке, должен лежать внутри `library/` или `index/texts/`, а каждое
  перемещение и удаление при установке, обновлении, удалении или откате проверяется на то, что оно не выходит за пределы
  рабочей папки. Настройки, которые пакет задаёт пустой рабочей папке, записываются экранированными; пути к программам
  читаются только из `assistant_x.local.toml`, никогда — из общего файла настроек. Векторы пакета проверяются (размеры,
  размерность, единичная длина, ключи только собственных фрагментов пакета, выборка кодируется заново, если модель есть
  на ПК). Пакет никогда не удаляет файлы: документы, проигравшие при объединении или удалённые, перемещаются в
  `inbox\_to_delete`.
- **Архивы в папке inbox**: имена проверяются до того, как что-либо будет записано (никаких абсолютных путей, `..`,
  ссылок), распакованный размер ограничен на случай ложных заголовков, глубина вложенности ограничена, а отклонённый
  архив аккуратно удаляется.
- **Документы**: ни один документ не исполняется. Файлы PDF, офисные файлы и изображения читаются PyMuPDF, LibreOffice
  (конвертация без интерфейса), Tesseract и DjVuLibre как отдельными программами; текст, скрытый от читателя (белый
  текст, крошечный шрифт), вырезается из текста для поиска, и о нём сообщается.
- **Поисковый сервер** (MCP) читает библиотеку и возвращает текст; изображения страниц ограничены папкой библиотеки.
  По HTTP (сервис библиотеки `assistant-x service`, к которому приложения обращаются через свой мост stdio, и
  `assistant-x serve --http`) он слушает только 127.0.0.1, каждый запрос должен нести bearer-токен из
  `%USERPROFILE%\.assistant_x\mcp_http_token.txt` (мост читает его сам: ни одна настройка приложения его не содержит;
  на Windows файл получает список доступа папки профиля пользователя, читать которую могут только сам пользователь,
  SYSTEM и администраторы; на Linux действует режим 0600, с которым он записывается), а Host или Origin, отличные от
  127.0.0.1 или localhost, отклоняются. Каждый инструмент несёт свои аннотации (только чтение, разрушающее действие),
  поэтому приложение спрашивает пользователя перед изменением; DeepSeek Harness и LM Studio по умолчанию получают только
  инструменты для чтения.
  Команды, которые изменяют библиотеку (`base_install`, `base_update`, `base_remove`, `intake_apply`), выполняются в два
  шага: план, затем подтверждение, повторяющее токен этого плана. Токен случаен, действует 30 минут, используется один
  раз и привязан к действию, его цели, рабочей папке и к тому, из чего был составлен план (файл пакета — по его манифесту
  и контрольным суммам, запись реестра удаляемого пакета, `meta.jsonl` пакета разбора): единственный вызов, записанный в
  документ, не может изменить библиотеку, а токен не подтверждает изменение в другой рабочей папке или для файла,
  заменённого после составления плана. Если клиент поддерживает MCP elicitation, сервер к тому же сам спрашивает
  пользователя перед изменением, и ответ «нет» его останавливает. Каждый такой вызов записывается в журнал
  (`.assistant_x\debug\changes.log`). Инструкции сервера говорят Claude, что текст документов — это данные, а фрагмент
  со словами, обращёнными к ИИ-ассистенту, помечается «Suspect text».

### Чего он не гарантирует

- **Содержание.** Claude читает тексты и карточки документа или пакета. Документ может содержать неверные факты или
  текст, написанный, чтобы управлять Claude («prompt injection»); пометка подозрительного текста — простая эвристика и
  пропускает то, чего не знает. Claude указывает страницу, чтобы пользователь мог её проверить.
- **Согласие пользователя.** Токен доказывает, что план был составлен в этом разговоре, но не то, что пользователь с
  ним согласился: текст, который заставит Claude вызвать план, а затем подтверждение в два шага, получит действительный
  токен. Если клиент не может сам спросить пользователя (нет MCP elicitation), последней защитой остаётся внимание
  самого пользователя: читайте план, который показывает Claude, и отвечайте «да» только на изменение, которое вы
  просили.
- **Ранжирование.** Векторы, прошедшие проверки, всё равно ранжируют фрагменты пакета по тому, что модель в них видит;
  пакет можно составить так, чтобы он часто оказывался в результатах.
- **Вызываемые программы.** LibreOffice, Tesseract, 7-Zip и DjVuLibre разбирают документы; уязвимость в любой из них —
  это уязвимость разбора. Обновляйте их (на офлайн-носителе версии зафиксированы).
- **Сам ПК.** Всё, что работает с правами пользователя на ПК, может читать библиотеку и настройки и вызывать локальный
  сервер; Assistant X — не песочница. Держите рабочую папку в папке, которую можете читать только вы.
- **Кто создал пакет.** Пакет не несёт подписи; устанавливайте пакеты от людей, которым доверяете.

## Область действия

Входят: код этого репозитория, установщик (Setup.bat, [`assistant_x/setup`](assistant_x/setup)), формат базовых
пакетов, MCP-сервер. Не входят: уязвимости Claude, сторонних программ и Python-пакетов (сообщайте о них их
разработчикам; сообщите нам, если Assistant X использует их небезопасно), а также атаки, для которых нужны собственные
права пользователя на ПК.
