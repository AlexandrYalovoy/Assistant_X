## Шаги по одному

Без `--background` та же команда работает на переднем плане и заканчивается одним объектом JSON: `ok`, `version`,
`python`, `python_source`, `command` (программа `assistant-x`), `workspace`, `device`, `apps` (подключённые),
`doctor`, `problems`, `next`. `--dry-run` показывает, что она сделала бы.

```
Setup.bat --online --yes --json [--base FILE] [--keep own|package] [--models] [--workspace DIR] [--machine-dir DIR] [--profile NAME]
```

Каждый шаг отдельно, с `command` из JSON:

- Модели (≈ 4,5 ГБ): `<command> download-models`. Без них поиск идёт только по словам.
- Приложения: `<command> connect auto` подключает все приложения, найденные на этом ПК ({{apps}});
  `<command> connect APP` — одно приложение; `<command> connect --check` — рукопожатие и поиск через запись каждого
  приложения.
- Базовый пакет: `<command> base inspect FILE` показывает, что в нём, и вопросы; после «да» пользователя
  `<command> base install FILE --confirm` (`--keep own|package`, если проверка спросила, чьи шифры сохранять;
  `--or-resume` продолжает прерванную установку; `--cpu` считает фрагменты без вектора на процессоре сколько бы их ни
  было: без него — до 5000, около часа, если видеокарты нет).
- Человек без агента дважды щёлкает `Setup.bat` (он предлагает `.axbase`, лежащий рядом) или позже `Install-Base.bat`.

## Если что-то не работает

Запустите `<command> doctor --json` и `<command> connect --check --json`. Каждая печатает один документ JSON; у
каждого сбоя в нём есть постоянный `code`, `message` и `fix` — команда, которую нужно выполнить (спросите пользователя
перед любой загрузкой или изменением его настроек), после чего запустите обе проверки снова. `ok: true` и `"ok": true`
у каждого приложения означают, что всё готово. Коды:

## Обновление («обнови мне ассистента» и ссылка на GitHub или GitFlic)

Сначала спросите пользователя: обновление скачивает колесо последнего релиза (несколько МБ) и ставит его рядом с
текущей версией. Затем выполните

```
<command> update --from https://github.com/OWNER/REPO --dry-run
<command> update --from https://github.com/OWNER/REPO
```

(или `https://gitflic.ru/project/OWNER/REPO`). Команда берёт только последний релиз с тегом, никогда черновик,
предварительный выпуск или последний коммит ветки; проверяет колесо по `SHA256SUMS` релиза и отказывается от релиза
без него; ставит программу в новое окружение `venv-<version>` машинной папки рядом со старым, заново подключает
приложения с новым python и запускает там `doctor --json`. Если какой-то шаг не удался, она подключает приложения
обратно к старой версии и удаляет новое окружение. Библиотеку, рабочее место и его настройки она не трогает. Скажите
пользователю перезапустить приложения; старое окружение остаётся для возврата.

## Какие есть инструменты

{{tools_table}}

Каждое приложение по умолчанию получает один инструмент `library`: он выполняет любую команду таблицы по её имени
и аргументам (`library(action="search_library", args={"query": "..."})`), поэтому приложение спрашивает один раз или
хранит одно правило разрешения; LM Studio получает команды справочного режима. `--full` даёт все инструменты по
отдельности, `--reader` — инструменты чтения по отдельности ({{reader_tools}}). Каждая команда, которая меняет
библиотеку, сначала просит у пользователя «да» на план.
