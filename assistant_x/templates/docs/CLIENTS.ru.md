# Приложения Assistant X

<!-- Made by assistant-x gen-docs from assistant_x/templates/docs/CLIENTS.ru.md: edit that file. -->

Assistant X открывает свою библиотеку любому приложению, которое понимает MCP. `assistant-x connect APP|auto` пишет
запись в настройки приложения; каждая запись запускает один и тот же stdio-мост, а он говорит с единственным сервисом
библиотеки рабочей папки на 127.0.0.1.

```
app ──stdio──> assistant-x mcp (the bridge) ──HTTP, token──> assistant-x service ──> the library, the models (once)
app ──stdio──> assistant-x mcp ─────────────────────────────┘
```

- **Мост** (`python -m assistant_x.server.bridge`): ничего тяжёлого не загружает, сразу отвечает на рукопожатие,
  незаметно запускает сервис, если тот не работает (и снова, если он пропал), и сам читает токен из служебной папки
  ПК: в настройках приложений нет никаких секретов.
- **Сервис** (`assistant-x service`): один на рабочую папку, модели загружаются один раз (на видеокарту, если она
  есть), каждый запрос — с токеном, принимаются только Host и Origin 127.0.0.1 и localhost; после 30 минут без
  запросов сервис закрывается, и локальная модель снова получает видеопамять.
- **Наборы инструментов**: `one_reader` (одна схема `library`, только чтение и экспорт, короткое руководство;
  по умолчанию у всех облачных агентов), `one_intake` (чтение и приём из inbox), `one` (та же схема со всеми командами, явно выбранная для пополнения),
  `all` (все инструменты по отдельности) или `reader` ({{reader_tools}}).
  `--compact`: описания в одно предложение, до {{compact_k}} основных результатов и до {{compact_norms}} дополнительных нормативных результатов, текстовые блоки ограничены {{compact_chars}} символами с
  подсказкой, как получить остальное.
- **Правила для модели**: инструкции сервера при рукопожатии, навык — если у приложения есть папка навыков, и
  инструмент `library_guide` для любого приложения (если приложение не передаёт инструкции или в чате нет навыков):
  фраза «подключись к библиотеке» или ключ «AX:» заставляет модель вызвать его первым.

`--full` (все инструменты по отдельности) и `--reader` (инструменты чтения по отдельности) сохранены для совместимости.
Явный выбор `assistant-x connect APP --tools one_reader|one_intake|one|reader|all` сохраняется при `assistant-x update`; без явного
выбора используется текущий режим по умолчанию. `--compact` даёт короткие ответы. Перед изменением рядом с файлом
настроек сохраняется его копия (`<name>.backup-<date>`, три последние), записи и комментарии других программ остаются,
повторный `connect` ничего не меняет, а файл, который не удаётся прочитать, не трогается: команда печатает запись,
которую нужно добавить вручную. `assistant-x disconnect APP` убирает запись и навык (навык, изменённый вручную, остаётся).

`assistant-x connect --list` показывает приложения (найдено, подключено, набор инструментов); `assistant-x connect
--check [APP]` запускает запись каждого подключённого приложения так же, как это делает приложение, проходит
рукопожатие, получает список инструментов и один раз ищет.

## Куда уходит текст

Библиотека и поиск по ней работают на ПК. То, что инструменты дают модели, уходит создателю этой модели (Anthropic
для Claude, OpenAI для Codex и ChatGPT, DeepSeek для моделей DeepSeek, Google для Gemini CLI и Antigravity, Moonshot AI
для Kimi, поставщик, выбранный в Cursor или Cline): вопрос, найденное (фрагменты, цитаты, шифры и названия), прочитанные
страницы, карточки, список документов, изображения страниц, а при разборе — черновики карточек с началом текста новых
файлов. С локальной моделью в LM Studio (или в DeepSeek Harness и Codex, направленных на LM Studio) ничего не покидает
ПК.

## Kimi Work

Kimi Work может сам установить программу по ссылке на репозиторий: агент следует [`INSTALL_FOR_AI.md`](../INSTALL_FOR_AI.ru.md),
затем создаёт или обновляет исходник персонального плагина, проверяет его и регистрирует через официальный механизм
Kimi. Пользователь открывает вкладку **Personal** и нажимает **＋**; перезапуск клиента не нужен. Обновление делается
только в исходнике с повышением локальной версии и повторной регистрацией, после чего пользователь нажимает **Update**.
Установленная копия напрямую не редактируется. Личные пути и настройки не публикуются.

Плагин использует один инструмент `library`: обычное чтение — `one_reader`, а для явно запрошенного пополнения в
исходнике выбирается полный `one`, с планом и подтверждением пользователя. `assistant-x connect kimi` настраивает Kimi
CLI / Kimi Code, но не устанавливает и не обновляет плагин Work — это отдельное действие.

25 ноября 2026 г. в Kimi Work на настоящей библиотеке проверены быстрый и глубокий ответы. Kimi CLI / Kimi Code и Kimi
Chat вживую отдельно не проверялись; их нельзя перечислять как проверенные только потому, что работает Work. Если MCP
недоступен, но агент может выполнить команду, используется одна резервная команда `assistant-x context "вопрос"
--mode fast|balanced|deep`, без изучения исходного кода и без написания собственного клиента. Режимы и измерения:
[`COST.md`](COST.ru.md).

## Codex и ChatGPT

Codex CLI, его расширение для IDE и приложение ChatGPT для компьютера читают один и тот же `~/.codex/config.toml`:
`assistant-x connect codex` подключает их все. На бесплатном тарифе ChatGPT Codex работает только в приложении для
компьютера (CLI и расширению для IDE нужен платный тариф), а при входе он может попросить номер телефона. Codex прячет
инструменты сервера за своим поиском инструментов: инструкции сервера и навык подсказывают модели, как их найти. С
маленькой локальной моделью через LM Studio (`codex --oss`) Codex сам занимает большую часть контекста (16 000 токенов
из 16 384, а при 32 768 — 68 000 входных токенов за ход), и некоторые шаблоны чата не принимают его системные
сообщения: Qwen3.5 в LM Studio отвечает «System message must be at the beginning» (его шаблон выдаёт ошибку на
системное сообщение не в начале); в проверке с моделью 9B даже с исправленным шаблоном Codex так и не добрался до
библиотеки. У облачных моделей приложения этих ограничений нет; собственный чат LM Studio с той же моделью работает
(`assistant-x connect lmstudio`).

## Чего нельзя

Локальный Codex использует мост. Для чтения и пополнения из inbox выберите `assistant-x connect codex --tools one_intake`.
Руководство показывает права подключения. Ключ `project_country = "KZ"` в разделе `[search]` файла настроек рабочей области отдаёт приоритет нормам страны проекта. Явно указанная в вопросе страна имеет приоритет. Перед применением требования проверьте редакцию и основание определения юрисдикции.
Профиль исключает удаление документов, изменение иерархии и управление пакетами. Команда intake_list показывает папку, форматы и состояние auto_apply.
Вложения чата требуется перенести в локальный inbox. Для проверки приёма используйте тестовую библиотеку.

Для браузерного ChatGPT требуется отдельное удалённое подключение MCP по HTTPS или Secure MCP Tunnel и разрешения рабочей области.
Чтение, приём и подтверждение в браузере с Assistant X требуют отдельной проверки. [Документация OpenAI](https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt).

| Подключение | Чтение | Приём из inbox | Подтверждение переноса |
| --- | --- | --- | --- |
| Локальный мост Codex, `one_reader` | Проверено по MCP | Отключён | Недоступно |
| Локальный мост Codex, `one_intake` | Проверено по MCP | Поддерживаются локальные файлы | План и токен с учётом локального `auto_apply` |
| Браузерный ChatGPT | Требуется пилот | Требуется пилот | Требуется пилот |
