# Как внести вклад в Assistant X

Спасибо, что хотите помочь. Предложения, вопросы и сообщения об ошибках приветствуются в виде issues; код,
документация, языковые пакеты и профили — в виде pull requests. Проект находится по адресу
https://github.com/AlexandrYalovoy/Assistant_X: issues и pull requests отправляйте туда (зеркало на GitFlic,
https://gitflic.ru/project/alexandryalovoy/assistant_x, — копия для чтения и клонирования). Все участники соблюдают
[Кодекс поведения](CODE_OF_CONDUCT.ru.md).

## Перед первым pull request

- **Соглашение с участником (Contributor License Agreement).** Любой вклад принимается на условиях
  [`CLA.md`](CLA.md): вы сохраняете своё авторское право и предоставляете автору лицензию, которая также позволяет
  впоследствии распространять проект под другими лицензиями. Примите его один раз — строкой, приведённой в
  [`CLA.md`](CLA.md), в описании своего первого pull request. Pull requests без неё не могут быть приняты.
- **Лицензии.** Код распространяется под GNU AGPL-3.0-or-later ([`LICENSE`](LICENSE)); папки с данными
  [`assistant_x/lang`](assistant_x/lang), [`assistant_x/profiles`](assistant_x/profiles) и
  [`assistant_x/schemas`](assistant_x/schemas) также доступны под CC-BY-4.0
  ([`LICENSES/CC-BY-4.0.txt`](LICENSES/CC-BY-4.0.txt), см. [`NOTICE`](NOTICE)). Чужой код или данные добавляйте только
  под лицензией, совместимой с этими, и указывайте их происхождение. Новая зависимость должна иметь лицензию,
  совместимую с AGPL-3.0; внесите её в [`NOTICE`](NOTICE), если это программа, модель или библиотека с собственным
  уведомлением.
- **Никаких чужих документов.** В тестах и примерах используются свободные или выдуманные документы с нейтральными
  названиями; никаких настоящих документов компаний, персональных данных и названий компаний или имён людей.

## Правила репозитория

- Всё в репозитории пишется на американском английском: код, комментарии, сообщения, документация. Слова, по которым
  распознаются документы (шаблоны, синонимы, стоп-слова языкового пакета или профиля), остаются на языке документов. У
  каждого документа для людей (README, CHANGELOG, ROADMAP, SECURITY, CONTRIBUTING, CODE_OF_CONDUCT, INSTALL_FOR_AI,
  docs/) есть русский двойник `name.ru.md`: меняйте оба в одном коммите; `tests/test_docs_pairs.py` проверяет, что их
  заголовки, блоки кода, ссылки и версии совпадают. Создаваемые программой берутся из `assistant_x/templates/docs`
  (`*.ru.md` и `ru.json`) через `assistant-x gen-docs`.
- Новый файл исходного кода начинается с тех же двух строк заголовка, что и остальные:
  `# Assistant X — Copyright (C) 2026 Alexandr Yalovoy` и `# SPDX-License-Identifier: AGPL-3.0-or-later`
  (при желании добавьте под ними свою строку об авторском праве).
- Форматируйте код командой `python -m ruff format .` (длина строки 125, pyproject.toml) и перед отправкой pull request
  запустите [`scripts\check.ps1`](scripts/check.ps1) (`ruff check`, `ruff format --check` и все тесты); добавьте тест
  на то, что вы меняете.
- Добавьте строку в [`CHANGELOG.md`](CHANGELOG.ru.md) под готовящейся версией.

## Релизы

- Версия хранится в `assistant_x.__version__` (`0.1`, позже `0.2`, `0.2.1` для исправления): оттуда её читают
  pyproject.toml, wheel и `assistant-x --version`.
- Релизы помечаются тегом `vX.Y[.Z]` на `main` (`v0.1` для `0.1`): аннотированный тег на коммите с зелёным CI,
  `git tag -a v0.1 -m "Assistant X 0.1"`.
- До появления тега заголовок версии в CHANGELOG выглядит как `## 0.1 — unreleased`; в коммите, на который ставится
  тег, вместо этого в нём указывается дата тега: `## 0.1 — 2026-MM-DD`. Затем следующая версия получает новый заголовок
  `unreleased`.
- Отправка тега запускает [`.github/workflows/release.yml`](.github/workflows/release.yml): он проверяет, что тег
  совпадает с версией кода, собирает wheel из чистой копии помеченного коммита, проверяет, что в нём ровно файлы
  `assistant_x/`, и создаёт релиз на GitHub с wheel, его SHA-256 и разделом CHANGELOG в качестве описания.
