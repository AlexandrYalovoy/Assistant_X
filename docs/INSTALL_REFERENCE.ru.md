# Установка Assistant X — справочник для агента

<!-- Made by assistant-x gen-docs from assistant_x/templates/docs/INSTALL_REFERENCE.ru.md: edit that file. -->

Сама установка — в [INSTALL_FOR_AI.ru.md](../INSTALL_FOR_AI.ru.md): одна команда в фоне и её состояние. Эта страница —
о том, что выходит за её рамки (версия 0.6.1): шаги по одному, коды проверок, обновление, инструменты сервера.
Читайте только нужный раздел.

## Шаги по одному

Без `--background` та же команда работает на переднем плане и заканчивается одним объектом JSON: `ok`, `version`,
`python`, `python_source`, `command` (программа `assistant-x`), `workspace`, `device`, `apps` (подключённые),
`doctor`, `problems`, `next`. `--dry-run` показывает, что она сделала бы.

```
Setup.bat --online --yes --json [--base FILE] [--keep own|package] [--models] [--workspace DIR] [--machine-dir DIR] [--profile NAME]
```

Каждый шаг отдельно, с `command` из JSON:

- Модели (≈ 4,5 ГБ): `<command> download-models`. Без них поиск идёт только по словам.
- Приложения: `<command> connect auto` подключает все приложения, найденные на этом ПК (`claude_desktop`, `claude_code`, `codex`, `dsh`, `lmstudio`, `gemini`, `antigravity`, `cursor`, `cline`, `kimi`);
  `<command> connect APP` — одно приложение; `<command> connect --check` — рукопожатие и поиск через запись каждого
  приложения.
- Базовый пакет: `<command> base inspect FILE` показывает, что в нём, и вопросы; после «да» пользователя
  `<command> base install FILE --confirm` (`--keep own|package`, если проверка спросила, чьи шифры сохранять;
  `--or-resume` продолжает прерванную установку; `--cpu` считает фрагменты без вектора на процессоре сколько бы их ни
  было: без него — до 5000, около часа, если видеокарты нет).
- Человек без агента дважды щёлкает `Setup.bat` (он предлагает `.axbase`, лежащий рядом) или позже `Install-Base.bat`.

## Если что-то не работает

Запустите `<command> doctor --json` и `<command> connect --check --json`. Каждая печатает один документ JSON; у
каждого сбоя в нём есть постоянный `code`, `message` и `fix` — команда, которую нужно выполнить (спросите пользователя
перед любой загрузкой или изменением его настроек), после чего запустите обе проверки снова. `ok: true` и `"ok": true`
у каждого приложения означают, что всё готово. Коды:

| Код | Что это значит | Как исправить |
| --- | --- | --- |
| `workspace-missing` | Рабочая папка библиотеки ещё не создана. | assistant-x init "{workspace}" |
| `folder-missing` | Не хватает папки рабочей папки. | assistant-x init "{workspace}" |
| `base-missing` | В библиотеке есть карточки, но нет поисковой базы. | assistant-x build |
| `model-missing` | Нет смысловой модели: поиск идёт только по словам. | assistant-x download-models (около 4,5 ГБ: сначала спросите пользователя) |
| `vectors-missing` | Фрагменты без векторов находятся только по словам. | assistant-x embed |
| `older-folder` | Старой служебной папкой ПК (до 0.5.1 или приватной копией Claude Desktop из Microsoft Store) может ещё пользоваться приложение, подключённое раньше. | assistant-x connect auto |
| `app-not-connected` | В приложении нет записи Assistant X. | assistant-x connect {app} |
| `models-in-app-package` | Модели ПК лежат в папке приложения из Microsoft Store: удаление или сброс этого приложения удалит их. | закройте приложения библиотеки на минуту (сервис библиотеки тогда остановится) и выполните любую команду assistant-x: она перенесёт модели в служебную папку ПК |
| `app-in-process` | Приложение запускает собственный сервер библиотеки (запись сделана до 0.5): он держит модели и видеокарту отдельно от общего сервиса остальных приложений. | assistant-x connect {app}, затем перезапустите приложение |
| `app-check-failed` | Запись приложения не отвечает на рукопожатие, список инструментов или поиск. | assistant-x connect --check {app} --json; если снова не работает: assistant-x debug-report |
| `search-words-only` | Поиск приложения отвечает только по словам (нет модели или векторов). | assistant-x doctor --json (он назовёт, какой модели или векторов не хватает) |
| `service-not-started` | Сервис библиотеки не запустился. | прочитайте конец журнала сервиса {log}; затем assistant-x doctor --json |
| `service-light` | Сервис библиотеки ищет на процессоре без переранжирования: видеокарту держит другой сервер библиотеки, поэтому ответы менее точные. | закройте приложения библиотеки на минуту (сервис библиотеки тогда остановится) и откройте одно снова; если не помогло: assistant-x doctor --json и assistant-x debug-report |
| `gpu-memory-low` | На видеокарте мало свободной памяти: модели поиска и локальная языковая модель тормозят друг друга. | в assistant_x.toml в разделе [search] задайте device = "cpu" (тогда библиотека оставит видеокарту локальной модели) или загрузите локальную модель с меньшим числом параллельных потоков |
| `skill-outdated` | Навык, загруженный в Claude Desktop, старше программы. | assistant-x skill; заархивируйте папку {folder} в zip и загрузите в Claude (Settings, Capabilities, Skills) |
| `tools-hidden` | Приложение прячет инструменты сервера за своим поиском инструментов (Codex). | найдите инструменты по запросу «assistant-x library library_guide search_library»; ресурсов у сервера нет |
| `sign-in-limits` | Тариф или вход ограничивают приложение: на бесплатном тарифе ChatGPT Codex работает только в приложении для компьютера, а при входе может попросить номер телефона. | используйте приложение ChatGPT для компьютера или подключите другое приложение: assistant-x connect auto |

## Обновление («обнови мне ассистента» и ссылка на GitHub или GitFlic)

Сначала спросите пользователя: обновление скачивает колесо последнего релиза (несколько МБ) и ставит его рядом с
текущей версией. Затем выполните

```
<command> update --from https://github.com/OWNER/REPO --dry-run
<command> update --from https://github.com/OWNER/REPO
```

(или `https://gitflic.ru/project/OWNER/REPO`). Команда берёт только последний релиз с тегом, никогда черновик,
предварительный выпуск или последний коммит ветки; проверяет колесо по `SHA256SUMS` релиза и отказывается от релиза
без него; ставит программу в новое окружение `venv-<version>` машинной папки рядом со старым, заново подключает
приложения с новым python и запускает там `doctor --json`. Если какой-то шаг не удался, она подключает приложения
обратно к старой версии и удаляет новое окружение. Библиотеку, рабочее место и его настройки она не трогает. Скажите
пользователю перезапустить приложения; старое окружение остаётся для возврата.

## Какие есть инструменты

| Инструмент | Что делает | Набор | Меняет библиотеку |
| --- | --- | --- | --- |
| `library_guide` | Вызывается первым, когда пользователь хочет работать с библиотекой (подключиться к библиотеке или базе знаний, ключ «AX:»): правила ответов (искать, читать, ссылаться на шифр и страницу, проверять цитаты) и полки этой библиотеки. | reader | нет |
| `search_library` | Найти фрагменты библиотеки по вопросу (по словам и по смыслу). | reader | нет |
| `read_pages` | Текст страниц документа или его части (шифр E-00006-02; номера страниц PDF), не больше 15 страниц за раз: ровно так, как он лежит в библиотеке. | reader | нет |
| `book_map` | Карта документа: оглавление с диапазонами страниц PDF; с номером страницы — часть оглавления вокруг неё и какие таблицы, рисунки, формулы и приложения лежат в её разделе. | reader | нет |
| `page_image` | Изображение страницы оригинала (номер страницы PDF), чтобы проверить рисунки, таблицы, формулы и графики, или показать пользователю страницу отсылки. | reader | нет |
| `export_references` | Скопировать файлы документов из отсылок в папку пользователя и собрать там один PDF процитированных страниц, по странице на лист, со ссылкой и названием сверху и выделенной цитатой. | reader | нет: пишет копии в папку, которую назвал пользователь |
| `verify_quote` | Проверить цитату перед дословным цитированием или число из таблицы: есть ли этот текст на указанной странице PDF документа (или на соседней)? | reader | нет |
| `document_info` | Карточка документа: обозначение, название, авторы, год, тип и полка, область применения, аннотация, темы, ключевые слова, термины, таблицы, ссылки, другие редакции, нумерация страниц. | reader | нет |
| `list_documents` | Список документов библиотеки с фильтрами; текст ищется в названиях, обозначениях и темах. | reader | нет |
| `intake_list` | Что лежит в inbox (собственные документы пользователя для разбора) и идёт ли сейчас разбор. | all | нет |
| `intake_run` | Запустить разбор inbox в фоне: распаковка, DOC/DOCX в PDF, распознавание сканов, тексты, черновики карточек. | all | пишет только свои рабочие файлы |
| `intake_status` | Ход разбора, переноса в библиотеку и пересчёта базы и следующий шаг — коротким ответом. | all | нет |
| `intake_card` | Черновики карточек обработанных файлов (T0001…): страницы, оценка распознавания, полка, обозначение, название; с tids — ещё заголовки и начало текста. | all | нет |
| `intake_save_meta` | Сохранить строки meta.jsonl пакета разбора (карточки, части, дубликаты, отклонённые) и проверить их. | all | пишет только свои рабочие файлы |
| `intake_apply` | Собрать карточки и перенести документы в библиотеку. | all | да, после «да» пользователя на план |
| `library_hierarchy` | Иерархия документов, по которой строятся ответы (какой вид документа главнее): показать действующую или записать свою иерархию пользователя в рабочую папку. | all | пишет только свои рабочие файлы |
| `library_remove` | Убрать документы из библиотеки (попавшие туда по ошибке): ничего не удаляется, оригиналы, карточки и тексты уходят в inbox\_to_delete\removed_<шифр>_<дата>, шифры остаются занятыми, база по словам пересобирается. | all | да, после «да» пользователя на план |
| `intake_reindex` | Достроить поисковую базу для новых документов. | all | пишет только свои рабочие файлы |
| `library` | Все команды библиотеки одним инструментом (по умолчанию у всех приложений: одно разрешение): action — имя команды, как её называет руководство (search_library, read_pages, page_image, export_references…), args — её аргументы по именам. | one | как команда, которую он выполняет |
| `base_export` | Библиотека в виде файла базового пакета (out: путь, оканчивающийся на .axbase). | all | пишет только свои рабочие файлы |
| `base_inspect` | Что сделает установка базового пакета (файла .axbase или его распакованной папки): проблемы, предупреждения, чьи шифры сохраняются, какие документы уже есть в библиотеке и вопросы к пользователю. | all | нет |
| `base_install` | Установить базовый пакет. | all | да, после «да» пользователя на план |
| `base_update` | Новая версия установленного базового пакета. | all | да, после «да» пользователя на план |
| `base_remove` | Убрать установленный базовый пакет из библиотеки: его документы уходят в inbox\_to_delete (не удаляются), собственные документы пользователя остаются. | all | да, после «да» пользователя на план |
| `base_status` | Как продвигаются проверка и установка базового пакета, вопросы проверки, отчёт об установке. | all | нет |
| `base_list` | Установленные в этой библиотеке базовые пакеты (версия, дата, документы) и собственные документы пользователя. | all | нет |

Каждое приложение по умолчанию получает один инструмент `library`: он выполняет любую команду таблицы по её имени
и аргументам (`library(action="search_library", args={"query": "..."})`), поэтому приложение спрашивает один раз или
хранит одно правило разрешения; LM Studio получает команды справочного режима. `--full` даёт все инструменты по
отдельности, `--reader` — инструменты чтения по отдельности (`library_guide`, `search_library`, `read_pages`, `book_map`, `page_image`, `verify_quote`, `document_info`, `list_documents`, `export_references`). Каждая команда, которая меняет
библиотеку, сначала просит у пользователя «да» на план.

## Команды

| Команда | Что делает |
| --- | --- |
| `init [FOLDER]` | создать рабочую папку |
| `doctor [--json]` | где что лежит и чего не хватает (`--json`: коды и исправления) |
| `intake` | разбор inbox: run, build, apply, status, ... |
| `build` | собрать поисковую базу из index |
| `embed` | векторы новых фрагментов |
| `mcp` | stdio-мост, который запускает приложение: он говорит с сервисом библиотеки |
| `service` | сервис библиотеки: один MCP-сервер на 127.0.0.1 для всех приложений |
| `serve` | MCP-сервер в процессе приложения (stdio; --http) |
| `search` | запрос из командной строки |
| `check` | проверить карточки (схему, профиль) и тексты |
| `report` | состояние библиотеки |
| `eval` | контрольные вопросы рабочей папки |
| `query-log` | что спрашивали приложения и сколько это заняло |
| `debug-report` | отчёт, который можно передать, когда что-то сломалось |
| `install` | окружение Python и подключение к приложениям |
| `status` | состояние установки, идущей в фоне (--json: одна строка) |
| `setup-intake` | LibreOffice, Tesseract, 7-Zip и DjVuLibre для разбора |
| `download-models` | смысловая модель и переранжировщик с HuggingFace |
| `prepare-media` | пакеты для установки без интернета (сборочный ПК) |
| `lock` | кто держит блокировку машины; команда под ней |
| `skill` | записать навык профиля рабочей папки (SKILL.md) |
| `connect` | подключить приложения этого ПК: claude_desktop, claude_code, codex, dsh, lmstudio, gemini, antigravity, cursor, cline, kimi |
| `disconnect` | убрать библиотеку из настроек приложения |
| `update` | заново подключить все подключённые приложения и обновить их навыки; --from URL: новый релиз |
| `gen-docs` | создать INSTALL_FOR_AI.md, AGENTS.md, docs/CLIENTS.md и плагин |
| `base` | базовые пакеты: export, inspect, install, update, remove |
| `remove` | отложить документы библиотеки в сторону (inbox\_to_delete), шифры остаются занятыми |
| `key-norms` | ключевые нормы проектных тем: найти, проверить по тексту страниц, записать |
