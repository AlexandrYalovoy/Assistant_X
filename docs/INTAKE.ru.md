# Разбор новых документов

Документы из `inbox` становятся оригиналами в `library` (под шифрами), JSON-карточками и текстами в `index`.
Разбор выполняется на этом ПК конвейером `assistant_x.intake.pipeline` (`assistant-x intake …`).
Как с ним работает Claude, описано в навыке (`assistant-x skill`), в разделе «How to sort new documents».

## Установка

`assistant-x setup-intake [--dry-run] [--no-install]` (или [`scripts\install_intake.bat`](../scripts/install_intake.bat)). В Linux и macOS команда
ничего не устанавливает: она ищет LibreOffice, Tesseract, 7-Zip и DjVuLibre в PATH и печатает команду менеджера
пакетов для недостающего (`sudo apt-get install …`, `sudo dnf install …`, `brew install …`, включая языки Tesseract
из языковых пакетов). В Windows:

- Python-пакеты необязательной группы `intake` из [`pyproject.toml`](../pyproject.toml) (pymupdf4llm, pymupdf_layout, psutil) — в
  окружение `.venv`;
- LibreOffice (DOC/DOCX/PPTX → PDF): через winget в режиме пользователя, иначе установщик из winget распаковывается
  командой `msiexec /a` в `%LOCALAPPDATA%\Programs\LibreOffice` — права администратора не нужны;
- Tesseract (UB-Mannheim) с языками используемых языковых пакетов (`tesseract` пакетов: по умолчанию rus и eng): через
  winget в режиме пользователя, иначе установщик распаковывается с помощью 7-Zip в
  `%LOCALAPPDATA%\Programs\Tesseract-OCR`; недостающие `<language>.traineddata` скачиваются с github.com/tesseract-ocr;
- 7-Zip (для .7z и .rar; zip и tar распаковываются без него);
- DjVuLibre (`ddjvu`, DjVu → PDF): через winget в режиме пользователя, иначе его установщик (`DjVuLibre.DjView`, хеш
  проверяет winget) распаковывается с помощью 7-Zip в `%LOCALAPPDATA%\Programs\DjVuLibre`;
- найденные пути записываются в `assistant_x.local.toml` (настройки этого ПК, не в Git; `assistant_x.toml` `[intake]` одинаков на
  всех ПК).

Для автономного носителя: `python -m assistant_x.setup.collect_programs` копирует установленные здесь Tesseract (rus, eng,
osd; 193 МБ), LibreOffice (без справки, со словарями ru и en и средой выполнения Visual C++ рядом с soffice; ≈1.1 ГБ),
7-Zip и DjVuLibre (инструменты командной строки без просмотрщика; если DjVuLibre здесь не установлен — официальный
установщик с зафиксированным SHA-256)
в `%USERPROFILE%\.assistant_x\programs` (`AX_PROGRAMS` задаёт другую папку; `VERSIONS.txt` описывает содержимое).
Оттуда программы запускаются без установки и находятся в первую очередь. Без этой папки используются установленные
программы.

Конвейер работает и без LibreOffice: DOC/DOCX/PPTX и электронные таблицы получают статус «skipped» с указанием причины;
без DjVuLibre (`ddjvu` ищется так же, как другие программы: `[intake] ddjvu`, `AX_DDJVU`, папка поставляемых программ
`DjVuLibre`, `Program Files\DjVuLibre`, PATH) файл DjVu пропускается с примечанием, в котором названа программа. Без Tesseract сканы
конвертируются без распознавания (OCR), такие страницы считаются в `no_ocr_pages`, а отчёт о качестве присваивает
документу приоритет «high».

## Конвейер

```
intake.bat  =  assistant-x intake run [--dry-run] [--workers N] [--resume]
   (no pause with AX_NOPAUSE, the exit code is that of the intake)
   preparing inbox (prepare.py): personal papers by the name of a file or folder (land register extracts,
                           insurance numbers, tax statements, mortgages, passports…: personal_papers of the
                           language packs, [intake] personal_words) → _to_delete without opening them, archives too;
                           archives → unpacked beside them (tools\unpack.py), the archive → _to_delete; with a
                           password → _to_delete ("an archive with a password", not an error of the batch);
                           letters (.eml .msg .oft) → their attachments into a folder of the letter's name
                           beside it (tools\letters.py; a forwarded letter is taken apart in turn), the letter →
                           _to_delete; macOS service files (__MACOSX\…, ._*) → _to_delete; what each extension is:
                           the one table core/formats.EXTENSIONS ("Formats" below)
   SHA-256: a duplicate by manifest.tsv, intake_events.tsv, the files of the batch (the journal hashes are read once)
   process pool (process.py → pool.py → work.py; only the main process writes the state):
     prep     → PDF (LibreOffice, images), hidden text (tools\hidden.py), a fingerprint of the text layer,
                the scanned pages, a broken font encoding (below)
     duplicates by content (dupcheck.THRESHOLDS: 8 % partial, 30 % a suspect, 60 % a duplicate at once only
                when it is the same edition, below)
     convert  → Markdown (tools\convert_md.py, reocr_empty.py, assemble_md.py); more than 100 lost symbols (U+FFFD)
                after it → prep again with OCR of the page images (the second guard of a broken encoding)
   quality report (quality_report.py), metadata draft (metadraft.py), summary (review.py)
Claude: meta.jsonl from meta_draft.jsonl (schema: meta_schema.py, assistant-x intake check-meta)
assistant-x intake build      → work\<DATE>\out (build.py; codes in codes.json)
   program files without a meta line (.exe .dll .msi, intake_cfg.PROGRAM_EXT, and those of the programs of the field
   of the profile: program_ext of profiles/<name>/documents.json; assistant_x.toml program_ext replaces the list)
   → _rejected\programs; a new version of a document of the library (versions.py, below):
   "replaces" takes its code, "other_version" keeps both
assistant-x intake apply [--dry-run | --resume]  (apply.py)
   moves into library / _duplicates / _rejected, a PDF beside a DOC, cards and texts into index,
   CATALOG.md and sources_to_update.md made again from all the cards, events, manifest.tsv, journal.md,
   empty folders of inbox; the base is marked behind the library (index_stale in its meta table, or
   index\index_stale.txt without a base): search_library says so first and `assistant-x check` warns, until
   `assistant-x build` reads the new documents (then `assistant-x embed`).
   The pipeline deletes nothing:
   it only moves into _to_delete, _duplicates, _rejected (the user deletes them).
   A transaction: the checks first, then out\apply.journal.json notes every move and step; an interrupted apply
   (the PC switched off) is refused until --resume, which goes on and adds no row twice. Missing folders of index
   are made first
```
Другие команды `assistant-x intake`: `status`, `todo [--by-folder]`, `brief [T0001 …]` (строка на файл: страницы, оценка распознавания,
полка, обозначение и название из черновика, путь — вместо `digest` для больших пакетов), `digest [T0001 …]`,
`groups [--write]`, `pack <folder> [--main T0001] [--write]` (все обработанные файлы папки — один документ: главный
файл и его части), `requeue T0001 …`, `draft`, `quality`, `journal [--check]`; все они принимают `--work DIR` (по умолчанию —
последний пакет, для `run` — сегодняшний). Части кода: `prepare.py` (inbox), `process.py` (пакет разбора и пул
процессов), `work.py` (стадии обработки файла; что они передают друг другу — в `results.py`), `review.py` (то, что читает Claude),
`build.py`, `apply.py`; команды собраны в `pipeline.py`. Общее у разбора и поиска лежит в `core`: структура текста
(`core/textmap.py`: заголовки, оглавление, подписи), журнал (`core/journal.py`), форматы.

Папка пакета разбора `.assistant_x\work\<DATE>`: `state.sqlite` (состояние: tid, путь, статус, причина, данные в JSON;
`state.py`), `src` (жёсткие ссылки на оригиналы), `pdf`, `txt`, `cache`, `md`, `log`, `fp`, `meta_draft.jsonl`,
`meta.jsonl`, `codes.json`, `quality.json`, `summary.md`, `intake_quality.md`, `out`. Отпечатки текстов библиотеки
для проверки на дубликаты кешируются в `.assistant_x\fingerprints` (один кеш на рабочую папку: `<code>.fp`, действителен только для того
текста, чей sha256 в нём записан).

### Что разбор не должен потерять

- **Дубликаты по содержанию и редакции** (`process.Batch.dup_verdict`). Файл, 60 % фраз которого и больше встречаются в
  тексте библиотеки (или в файле того же пакета), сам по себе считается дубликатом, только если это та же редакция:
  совпадает 90 % фраз и больше (`THRESHOLDS["same"]`), число страниц различается не больше чем на 10 % (`"pages_apart"`)
  и нет другого обозначения того же документа (обозначения с первых страниц без года, `versions.key`: там ГОСТ Р
  51858-2002, здесь ГОСТ Р 51858-2020). Иначе — а также начиная с 30 % — файл остаётся подозрительным: состояние хранит
  `suspect` и `suspect_why`, `intake brief` показывает «like N-00005?», а черновик задаёт Claude вопрос «тот же
  документ или другая редакция» (`{"dupof": …}` или оставить: `replaces` / `other_version` для документа библиотеки).
  Совпадение SHA-256 — всегда дубликат. DOC/DOCX рядом с более ранним сканом того же текста — сохраняются оба (`rival`).
- **Сканированные страницы** (`work.scanned`). Страница уходит на распознавание, когда растровые изображения покрывают
  70 % её площади и больше (их рамки объединяются и обрезаются по границе страницы), а текстовый слой разрежен (меньше 1
  символа на см²; у страницы с текстом — 4 и больше): скан со штампом, колонтитулом или водяным знаком в текстовом слое
  всё равно распознаётся. Страница, изображения которой не дают рамок, и любая страница PDF, полученного из офисного
  файла, считается сканом по прежнему правилу (меньше 80 символов и картинка). Сканированные страницы передаются в
  конвертацию (`jobs.json` `"ocr_pages"`); `reocr_empty.py` распознаёт те, что конвертация не прочитала. Текстовый слой
  такой страницы сохраняется после текста распознавания, если OCR не прочитал большую часть её слов (`assemble_md.py`;
  источник страницы — `ocr`).
- **Сломанная кодировка шрифта** (`work.broken_encoding`) выявляется на подготовке, до конвертации, по первым 5 страницам с
  текстом (не меньше 200 букв): 30 % букв не относятся ни к одному языку активных пакетов («Íàñòîÿùèé»: кириллическая
  кодовая страница, прочитанная как Latin-1), 10 % потерянных символов или 80 % слов, неизвестных словарю библиотеки
  (когда в нём 1000 словоформ и больше; на подготовке он не строится). Такой файл сразу распознаётся по изображениям
  страниц (`imgocr`, причина записывается в состояние); больше 100 символов U+FFFD после конвертации — вторая линия защиты.

**Сверка карточки с текстом** (`meta_schema.text_checks`, выполняют `check-meta` и `build`): обозначение должно стоять
на первых 3 страницах текста своего файла или в имени файла (после OCR достаточно его цифр), а название должно иметь
хотя бы одно общее слово с первыми страницами текста длиной 2 страницы и больше — иначе это ошибка (строка, написанная
для другого tid); год, которого нет в тексте, и меньше половины найденных в нём ключевых слов на языках документа —
предупреждения.

**Дайджест** (`intake digest`, MCP-команда `intake_card` с tid) показывает текст в зависимости от жанра в черновике
(`review.DIGEST`, одна таблица частей и их размеров): у стандарта — титульный лист и область применения, у статьи или
диссертации — титульный лист и аннотацию, у выпуска журнала, сборника трудов или книги — титульный лист и оглавление,
у паспорта или руководства — характеристики; у любого другого документа — начало текста. Заголовки частей берутся из
слов языковых пакетов (`digest_heads`).

meta.jsonl: по строке на файл — документ `{tid, sec, doc_type, en, au, …the doc fields of the card…}`, часть
`{tid, part, what}`, дубликат `{tid, dupof, why}`, отклонённый файл `{tid, drop}` (`meta_schema.py`). Строка документа
проверяется так же, как будет проверяться его карточка (`core/card.validate`: схема, языки карточки, полки, ограничения).
Действует ли документ, решает пользователь: статуса действия у карточки нет.

## Форматы

Что разбор делает с файлом, определяется видом его расширения (`core/formats.EXTENSIONS`). Файл не в формате PDF
получает собственный PDF (`work\<DATE>\pdf\<tid>.pdf`), который ложится в библиотеку рядом с оригиналом (`file.pdf_copy`
карточки): страницы цитаты — это страницы этого PDF, поэтому они не меняются.

| Вид | Расширения | Как |
|------|------------|-----|
| pdf | pdf | как есть; сканированные страницы — через OCR |
| office | doc docx docm rtf odt ppt pptx pps ppsx odp | LibreOffice → PDF |
| spreadsheet | xls xlsx xlsm xlsb ods | по умолчанию остаются во входящих (`spreadsheets = "skip"`); с `include`: LibreOffice → PDF для страниц; каждый лист — Markdown-таблица `## Sheet: <name>` в конце той страницы, где видны его первые ячейки (`tools\sheets.py`; XLS, XLSB, ODS сначала переводятся LibreOffice в XLSX; не больше 2000 строк и 60 столбцов листа, об усечении сообщает примечание) |
| ebook | epub fb2 mobi xps oxps | PyMuPDF раскладывает книгу по страницам A4, её оглавление сохраняется как закладки (MOBI — насколько его открывает PyMuPDF) |
| text | txt md markdown html htm xhtml | PyMuPDF раскладывает текст по страницам A4; файл TXT или Markdown читается как UTF-8, а если не получается — в устаревшей кодовой странице того языкового пакета, который даёт больше всего стоп-слов (`encodings` пакетов: cp1251, koi8-r, cp866, cp1252); Markdown раскладывается так, как написан |
| djvu | djvu djv | DjVuLibre (`ddjvu -format=pdf`) → PDF из изображений страниц, затем OCR; без DjVuLibre файл пропускается |
| image | jpg jpeg png tif tiff bmp | PyMuPDF → PDF, затем OCR |
| archive | zip 7z rar tar tgz tar.gz tar.bz2 tar.xz gz | распаковывается рядом, архив — в `_to_delete` |
| letter | eml msg oft | вложения извлекаются рядом (`.eml` — стандартной библиотекой, `.msg`/`.oft` — из составного файла Outlook; встроенный элемент, не являющийся файлом, упоминается в событии), письмо — в `_to_delete` |

Любое другое расширение получает «skipped: decide by hand» (пропущено, решите вручную). Вид в карточке
(`file.format.kind`) для этих видов — `ebook`, `text` или `spreadsheet`; файл DjVu считается сканом (`pdf_scan`).

**Структура заголовков файла** (`tools\outline.py`): закладки PDF (с их страницами) или, для DOCX без закладок, его стили
заголовков (Heading 1…9 или уровень структуры; страница каждого заголовка находится по его тексту) — первый источник
структуры: они записываются в `<code>.pages.json` (`"outline"`), черновик берёт из них оглавление карточки, а база
хранит их (`given_outline`) для карты книги. Заголовки, угаданные по тексту, — запасной вариант (`core/textmap.build`).

## Формат текста (AX text 1)

`index\texts\<code>.md` — текст документа в том виде, в каком его читают поиск и Claude; его можно править вручную
(исправить ошибку распознавания, поправить таблицу); из него строится поисковая база (`assistant-x build`). Его правила
(`core/formats.py`, `TEXT_FORMAT = "1"`) соблюдает `tools\assemble_md.py` и проверяет `assistant-x check`:

- **Кодировка и строки**: UTF-8 без BOM, концы строк LF (текст с CRLF — предупреждение проверки), Unicode NFC
  (буква с диакритическим знаком — один символ).
- **Страницы**: каждая страница PDF начинается с собственной строки-маркера `=== page N ===`, где N — номер страницы
  PDF (а не печатный номер), по порядку, по одному маркеру на каждую страницу (текст, маркеры которого не совпадают с его
  PDF, — ошибка проверки, когда оригинал под рукой). Строка тела, которая читалась бы как маркер, записывается с обратной
  косой чертой в начале: `\=== page 3 ===` (и ещё одной обратной косой чертой перед строкой, в начале которой они уже
  есть); поиск отдаёт такую строку без обратной косой черты.
- **Что может содержать тело**: заголовки Markdown (`#`…`######`), абзацы, списки, таблицы GFM (строка заголовка,
  строка-разделитель `|---|`, строки таблицы). Не допускаются: сырой HTML, невидимые символы (нулевой ширины, управления
  направлением текста, теги Unicode, селекторы вариантов: разбор их удаляет, проверка о них предупреждает), мягкий
  перенос (записывается как «-»).
- **Переносы**: текстовый слой PDF читается с соединением слов, разорванных в конце строки (PyMuPDF
  `TEXT_DEHYPHENATE`); на странице OCR слово, разорванное дефисом в конце строки, соединяется, только если словарь
  библиотеки (`.assistant_x\ocr_vocab.txt`, см. «Оценка распознавания») знает слово целиком.
- **Что известно о каждой странице**: `index\texts\<code>.pages.json` рядом с текстом; его пишет разбор, и он
  перемещается, заменяется (`assistant-x intake redo`) и откладывается (при новой версии) вместе с текстом:

  ```json
  {"format": 1, "pages": {"12": {"source": "ocr", "ocr_score": 83.5, "label": "218", "flags": ["complex_table"]}},
   "outline": [[1, "1 General", 3], [2, "1.1 Scope", 3]]}
  ```

  `outline` (когда файл его даёт: закладки PDF, стили заголовков DOCX): `[level, title, PDF page or null]` (уровень,
  заголовок, страница PDF или null).

  `source`: `layer` (простой текстовый слой PDF, страница не конвертировалась), `markdown` (конвертирована с сохранением
  разметки), `ocr` (конвертирована и распознана OCR), `fallback` (конвертация не удалась, взят текстовый слой);
  `ocr_score`: оценка распознавания страницы; `label`: печатный номер страницы из меток страниц PDF, `null`, если
  меток в PDF нет (тогда используется `page_offset` карточки); `flags`: `complex_table` (таблица, в строке которой
  другое число ячеек, чем в заголовке: объединённые ячейки, числа нужно сверить с изображением страницы), `formula`
  (строка, оканчивающаяся номером уравнения), `garbled` (четверть слов неизвестна), `doubled` (каждая фраза дважды),
  `dpi_reduced` (OCR с пониженным разрешением); `layer` (только на некоторых страницах): `kept` или `added` (видимый
  текстовый слой скана, см. «Оценка распознавания»). Текст без этого файла всё равно участвует в поиске (предупреждение
  проверки); после ручной правки, которая добавляет или удаляет страницы, исправьте этот файл или удалите его.

## Карточки

Карточка — это `index/cards/<code>.json`, строгий JSON, проверяемый по JSON Schema [`assistant_x/schemas/card-1.json`](../assistant_x/schemas/card-1.json)
(`core/card.py`); это единственный источник истины о документе: `CATALOG.md`, `sources_to_update.md` и таблица `docs`
базы строятся из карточек, первые два файла никто не правит вручную.

- Шифр: буква полки и пять цифр, `N-00012`; части документа из нескольких файлов — `N-00012-02`.
  Выдаётся следующий свободный номер полки (`<work>/codes.json` хранит его для пакета разбора).
- `doc` — что представляет собой документ; заполняет Claude по черновику: `title`, `designation`, `authors`, `year`,
  `publisher`, `edition`, `lang`, `scope` (≤ 300 символов), `summary` (≤ 800), `questions` (≤ 5), `topics` (1–8
  идентификаторов), `keywords` (≤ 30 на язык), `terms` (≤ 40), `toc` (≤ 300 записей, только `pdf_from`: запись
  заканчивается там, где начинается следующая), `tables` (≤ 100), `references` (только обозначения: база сама
  сопоставляет их с шифрами), `units` и `serial` выпуска журнала или сборника трудов, `other_versions`, `adopts`
  (иностранные стандарты, которые принимает национальный, в том виде, как их называет его титульный лист:
  `ISO 10424-2:2007`; находятся при поиске вместе с обозначением), `amends` (обозначение стандарта, к которому относится
  изменение), `page_offset`, `note`.
- `file` — что известно о файле под этим шифром: `format` (`kind`, число страниц, распознанные страницы, оценка 0–1),
  `library` (место, `/` между папками), `source_name`, `sha256`, `size`, `text`, `pdf_copy`, `hidden_text`, `issues`
  (что не так с источником: из них строятся источники для обновления), `parts`.
- `intake` — пакет разбора, дата и `personal` (по умолчанию false; true только для пополнения, которое пользователь
  попросил держать отдельно, см. «Личные документы» ниже).
- Верхний уровень: `schema` (1), `code`, `section` (полка), `doc_type` (жанр).
- Языки: каждый текст, который ищется по точным словам, — это словарь `{"en": …, "ru": …}`. Английский есть всегда, а
  также каждый язык, на котором читаются документы (`[documents] languages` в `assistant_x.toml`: по умолчанию русский и
  английский), при любом профиле.
  `scope`, `summary`, `questions`, `note` и `units[].summary` пишутся только на английском: поиск по смыслу (bge-m3)
  находит их по вопросу на любом языке.
- Две оси классификации, обе предлагает черновик и подтверждает Claude: `doc_type` — универсальный жанр (law,
  regulation, standard, guideline, contract, court_decision, clinical_guideline, book, textbook, handbook,
  serial_issue, proceedings, article, thesis, report, manual, datasheet, drawing, project, presentation,
  lecture_notes, dataset, other), и `section` — полка: одни и те же полки в каждой библиотеке
  ([`assistant_x/schemas/shelves.json`](../assistant_x/schemas/shelves.json): N Стандарты, L Литература, P Проекты и отчёты, E Паспорта и руководства, R Нормативные акты и
регламенты, J Журналы и статьи, X Прочее; для каждой — буква, папка, названия на английском и русском, что на неё
  кладётся). Каждый жанр стоит ровно на одной полке, поэтому полка следует из жанра; Claude кладёт документ на другую
  полку только с обоснованием. Единый набор полок сохраняет совместимость шифров всех библиотек и пакетов баз.
- Карточка записывается с отсортированными ключами, отступом в один пробел, буквами UTF-8 как есть, концами строк LF и
  переводом строки в конце: одна и та же карточка даёт одни и те же байты, поэтому `assistant-x build` перечитывает
  только карточки с изменившимся sha256. Версия схемы — 1; `card.migrate` — цепочка последующих версий (пока пустая).
  Библиотеки с Markdown-карточками прежних версий не переносятся: новая библиотека создаётся собственным разбором.

Черновик (`metadraft.py`) предлагает по тексту: жанр и полку (по словам языковых пакетов, `doc_type_words` пакетов и
профиля; каждый жанр из `schemas/card-1.json` пробуется в его порядке; первым — обозначение стандарта), название и
обозначение на языке документа,
год, издателя, языки, оглавление со страницами PDF (`search/bookmap.py`), таблицы, обозначения, на которые ссылается
текст, и статьи выпуска журнала по его странице содержания. Claude сверяет черновик с текстом и добавляет то, чего не
может код: английские варианты, краткое содержание, темы, ключевые слова.

Обозначения стандарта: в каждом классе номеров допускаются дефис, короткое и длинное тире (`GOST 33000—2014` с
титульного листа). Из обозначений, стоящих на титульном листе самостоятельно, национальное (`national_standard`
пакетов) побеждает напечатанное рядом иностранное; иностранное в скобках сразу после него попадает в `adopts`.
Имя файла даёт обозначение, если в тексте его нет, и его форму, если это тот же номер с годом, который в тексте опущен.
Английское название стандарта — ближайшая к его обозначению на титульном листе строка латинских букв из трёх слов и
больше (если такой нет — пословный перевод названия заглавными буквами). Первая страница, начинающаяся словами изменения
(`amendment` пакетов: «Изменение № 1», «Поправка»), даёт черновик жанра standard с `amends`, равным обозначению, которое
она называет: об изменении никогда не спрашивают как о новой версии его основного документа. Угаданное оглавление
отбрасывает запись, повторённую дважды на одной странице, и служебные строки титульного листа (`not_heading` пакетов:
«Дата введения»).

## Новая версия документа

Черновик (`metadraft.write_drafts`) сравнивает каждый файл с документами библиотеки (`versions.py`): то же обозначение с
другим годом (ГОСТ Р 51858-2002 в библиотеке, ГОСТ Р 51858-2020 в inbox) или очень похожее название (80 % общих
слов). Такой файл получает `version_of` и `question` в `meta_draft.jsonl`; Claude спрашивает пользователя и записывает
ответ:

- `"replaces": "N-00001"` — новый файл получает шифр N-00001 (его полка тоже должна быть N); старый оригинал, его
  карточка и текст уходят в `inbox\_to_delete\replaced_<DATE>` (ничего не удаляется), строкой каталога становится новая,
  в событиях записывается «к удалению: заменён новой версией» и «готово: новая версия». Документ из нескольких файлов
  не заменяется (оставьте оба).
- `"other_version": "N-00001"` — новый файл получает собственный шифр; обе карточки ссылаются друг на друга в
  `doc.other_versions`.

**Шифры между пакетами.** `build` выдаёт шифры под блокировкой `index\codes.lock` (только один процесс за раз читает
занятые номера и пишет `codes.json`). Два пакета, собранные один за другим, получают одни и те же следующие свободные
номера; пакет, который применяется вторым, ещё до первого перемещения видит, что карточка библиотеки заняла шифр из
его пакета, выдаёт этим документам следующие свободные шифры и собирает пакет заново (карточки, тексты, перемещения,
события — всё, где упоминается шифр), детерминированно, в порядке tid. Номер никогда не выдаётся дважды:
`index\codes.json` хранит наибольший выданный номер для каждой буквы полки, поэтому номер изъятого или заменённого
документа не возвращается. Сборка, которая не может захватить `codes.lock` в течение двух минут, останавливается и
сообщает об этом (блокировку держит другая сборка или установка базы).

**В Linux и macOS** инструмент запускается с ограниченным адресным пространством (`resource.prlimit` RLIMIT_AS; для
текущего процесса — `setrlimit`), класс приоритета задаётся значением nice (ниже обычного — 10, idle — 19), а
процессоры — через `os.sched_setaffinity`, если система это поддерживает; о том, чего в системе нет, один раз
сообщается в stderr, и работа продолжается, а psutil, как и прежде, следит за деревом процессов (`intake\limits.py`).
В Windows по-прежнему используются Job Objects. Поскольку пиковое потребление задания там прочитать нельзя, упавший
инструмент считается превысившим предел памяти, если об этом говорит его вывод (`MemoryError`, "Cannot allocate memory",
`std::bad_alloc`, "out of memory") или его завершило ядро (SIGKILL).

Надёжность: прерванный запуск (Ctrl+C, сбой) продолжается той же командой `run` — файлы «в работе» возвращаются в
очередь, готовые страницы OCR берутся из кеша. Каждая программа (LibreOffice, OCR, hidden.py) работает внутри Windows
Job Object: предел памяти на всё дерево процессов, тайм-аут, дерево завершается целиком, окна с ошибками не появляются
(`limits.py`; вне Windows — надзор через psutil). Превышение пределов даёт статус «error» с указанием причины. Процесс
пула, дважды упавший на одном файле, помечает его как ошибку. Профили LibreOffice — короткие пути в
`%TEMP%\at_lo\<slot>`.

Режим `inproc` (по умолчанию): рабочий процесс один раз импортирует PyMuPDF, pymupdf4llm и инструменты и вызывает
стадии как функции; LibreOffice остаётся отдельной программой. Каждый рабочий процесс находится в собственном Job Object
(предел `worker_memory_mb` распространяется на него и на запускаемые им программы). Задача, превысившая свой срок
(prep — `soffice` + `hidden` + 600 с, convert —
2 × `convert` + 1800 с), или рабочий процесс, упёршийся в предел памяти: рабочий процесс завершается и создаётся заново,
файл получает «error» с причиной («time exceeded», «memory cap exceeded»), остальные рабочие процессы продолжают работу.
Упавший рабочий процесс: файл возвращается в очередь, повторное падение — ошибка. Исключение в инструменте — ошибка
файла с текстом исключения. Рабочий процесс заменяется новым после 100 задач. Модели разметки (ONNX) ограничены одним
потоком без активного ожидания (`tools\onnx_threads.py`, любая сессия, в том числе созданные pymupdf4llm): по умолчанию
onnxruntime занимает все ядра, и при нескольких документах сразу процессор тратился на ожидание.

Нагрузку на ПК (`balance.py`) определяют измерения на любом ПК, без номеров ядер и моделей процессоров. При запуске
проводится обследование: CPU (логические процессоры, ядра, E-ядра, если процессор гибридный), RAM, видеокарта. Бюджет:
рабочий процесс — одно ядро (один поток onnxruntime, OpenMP, MKL, torch; это меняет `threads` из `[intake]`, а
`ocr_threads` по-прежнему задаёт потоки Tesseract); «свободен» — столько рабочих процессов, сколько логических
процессоров сверх резерва в 2, сколько помещается в доступную память за вычетом резерва (≥ 4 ГБ или 15 % RAM, смотря что
больше; по трети `worker_memory_mb` на рабочий процесс), и не больше `workers`; «за компьютером» — не больше числа ядер
− 2 и доли `cpu_share_active`. Регулятор (поток в `pool.py`, каждые 4 с) измеряет общую загрузку CPU и долю наших процессов
(учёт Job Object: чужая нагрузка видна отдельно), диск (занятость = 100 − `% Idle Time` и задержка
`Avg. Disk sec/Transfer`), доступную память, время с
последнего ввода (`GetLastInputInfo`), температуру (LibreHardwareMonitor / OpenHardwareMonitor, если установлены,
иначе `MSAcpi_ThermalZoneTemperature`, видеокарта — `nvidia-smi`; без датчика перегрев виден по падению частоты
под нагрузкой, `% Processor Performance`) и удерживает: «свободен» (нет ввода `idle_minutes` минут и нет чужой нагрузки) —
общую загрузку CPU 70–85 %; «за компьютером» — 40–55 %. Пользователь вернулся — лишние рабочие процессы за один шаг
встают на паузу; ушёл — каждые 45 с добавляется ещё один рабочий процесс. Всегда: приоритет ниже обычного и низкий
приоритет диска, 2 свободных процессора, резерв памяти, температура ниже `temp_max_c`; диск замедляет работу только в
состоянии «за компьютером» и только когда передача в среднем занимает больше 50 мс (быстрый SSD, занятый на 100 % при
0.2 мс, — не повод). Аварийные ситуации: память < 1.5 ГБ, CPU > 90 % или диск, занятый на 90 % при передачах дольше
200 мс, дольше 15 с — половина рабочих процессов встаёт на паузу; память < 1 ГБ — все.
`balance.log` раз в минуту получает строку о нагрузке, даже если ничего не меняется ("cpu 42 % (ours 31 %), workers 8/8
active, mem 17.2 GB free, disk 1 ms, gpu 0 %"), а `summary.md` — среднюю долю CPU за пакет и минуты с приостановленными
рабочими процессами. Оставшееся время в `intake status` считается как стоимость файлов (`schedule.cost`: текстовые
страницы, сканы, страницы с картинкой; ещё не подготовленный файл — по размеру), делённая на выполненную до сих пор
стоимость в секунду, и сообщается, когда готовы 5 файлов: дешёвые файлы идут первыми, поэтому расчёт по страницам в
секунду обещал бы слишком много. Пауза: рабочий процесс не получает новых задач, его дерево процессов (с LibreOffice
и Tesseract) получает приоритет IDLE до конца текущей задачи; при аварии и перегреве дерево приостанавливается, а время
паузы не засчитывается в ограничение времени задачи. Решения записываются в
`work\<batch>\balance.log` (время, состояние, активные/всего, измерения, причины).
Тяжёлые файлы (больше `heavy_mb`) идут в конце и по одному; `assistant-x intake run --resume` продолжает последний пакет.
Предел памяти задачи определяется по числу страниц, известному после prep: до 300 страниц — `worker_memory_mb`, до 800 —
6 ГБ, больше — 8 ГБ, и такой документ обрабатывается один (не больше половины RAM). Если рабочий процесс упёрся в предел,
документ повторяется один раз с удвоенным пределом в новом рабочем процессе (в выводе и в состоянии: `memory_retry`),
а во второй раз это ошибка файла.
Одна тяжёлая задача на ПК (`core/lock.py`, блокировка `%USERPROFILE%\.assistant_x\heavy.lock`, журнал `heavy.log` рядом): `run`,
`redo`, `build`, `apply`; если блокировка занята, они печатают, кто её держит, и завершаются с кодом 3, а с `--wait` —
ждут. Другие тяжёлые команды под блокировкой: `assistant-x lock --wait "embed" -- assistant-x embed`; кто её держит:
`assistant-x lock`. Прежний режим: `stage_mode = "subprocess"` в `assistant_x.toml` `[intake]` или
`set AX_STAGE_MODE=subprocess`. Замеры: `debug\intake_timing\timings.md` (не в Git).

## Оценка распознавания

Каждый текст получает оценку 0–100 (`tools\ocr_score.py`, пороги — `QUALITY` в [`assistant_x\core\common.py`](../assistant_x/core/common.py), ключи
`ocr_*`). Её основа — доля неслов: слово считается известным, если оно встречается в 3+ документах библиотеки
(словарь `.assistant_x\ocr_vocab.txt`; перестраивается последним шагом каждого `assistant-x intake apply`, о чём
сообщает строка в его выводе, и вручную командой `assistant-x intake vocab`; около минуты). Пока словарь
мал (меньше 1000 словоформ: новая библиотека), слова оцениваются только по их виду, чтобы чистый документ не был
назван плохим. Под словарём библиотеки лежит начальный словарь каждого языкового пакета (`lang/<code>/vocab.txt`):
он составлен из слов данных пакета, а для английского — ещё и из документации (сторонние частотные списки не
поставляются); он учитывается, только когда словарь библиотеки становится достаточно большим. Ошибками считаются: буквы двух пакетов в одном слове (латиница вперемешку с кириллицей), U+FFFD и «сломанный»
шрифт (Latin Extended-B), мусор из знаков, обрывки распознавания (двухбуквенные сочетания вне списков языковых пакетов,
пара одинаковых заглавных, лишние одиночные буквы). Числа, коды и сокращения нейтральны. Для страниц OCR
уверенность Tesseract входит в оценку с весом 0.25. Чистый текстовый PDF даёт 95–100, мусор — ниже 50. Оценка сверена
с точностью на 20 страницах, просмотренных глазами: `debug\ocr_quality\review.md`.

Страница OCR обрабатывается так (`tools\ocr_page.py`; pymupdf4llm вызывает его вместо встроенного Tesseract):

- **распознавание**: программа Tesseract (`--oem 1`, LSTM, как в PyMuPDF), `tsv txt`; слова ложатся на страницу
  невидимым текстом, каждое в своей рамке, — так сохраняются пробелы в таблицах;
- **поворот** (OSD, `--psm 0`, на копии половинного размера) проверяется на каждой странице OCR: при уверенном повороте
  на 90/180/270 страница распознаётся повёрнутой, и её текст заменяет Markdown;
- **слабая страница** (уверенность ниже 60 — с 2026-10-24, раньше было 70 — или больше 25 % неслов) распознаётся ещё
  дважды: при 400 dpi и в чёрно-белом виде; остаётся вариант с лучшей оценкой;
- **проверка потерь**: если Markdown после анализа разметки сохранил меньше 60 % распознанных слов, страница получает
  простой текст Tesseract (или он добавляется после Markdown страницы, распознанной частично).

Страница с читаемым текстовым слоем из 8 слов и больше (скан, которому издатель дал видимый текст, текстовая страница с
картинкой) читается один раз, без проверки поворота и повторов. Когда 70 % различных распознанных слов уже есть в слое
(в нижнем регистре, буквы и цифры), распознавание отбрасывается и страницей становится её слой (`"layer":
"kept"` в `<tid>.pages.json`); иначе добавляются только распознанные слова, которых в слое нет (подпись к рисунку,
штамп: `"layer": "added"`). Такой слой часто смещён относительно глифов под ним, поэтому изображение по-прежнему их
показывает: невидимая копия всей страницы заставила бы анализ разметки извлечь каждую фразу дважды. Для подстраховки
оценка считает для каждой страницы из 30 слов и больше долю словесных 3-грамм, встречающихся дважды (`repeated`);
начиная с 0.4 страница получает флаг `doubled` (поиск учитывает его так же, как `garbled`), документ, в котором таких
страниц больше 10 %, попадает в `intake_quality.md` («извлечь текст заново»), а `assistant-x intake redo` заменяет
текст библиотеки, если доля удвоенных страниц снижается на 30 пунктов (или средняя доля падает с более чем 0.4 до
менее чем 0.1) и при этом сохраняются известные слова. Строка или предложение, слово в слово повторяющие предыдущие,
отбрасываются при сборке. В строках таблицы Markdown последовательность из 17 букв и больше, не являющаяся словом
(ячейка, в которой OCR потерял пробелы), разбивается на самую дешёвую последовательность слов словаря (словоформа — 1,
стоп-слово из одной или двух букв — 1.6, слово, известное по основе, — 2.5, форма из трёх букв — 3; соединительная
гласная сложного слова, `compound_links` пакетов, словом не считается), причём слово, разорванное в конце строки ячейки,
сначала соединяется; разбиение, в котором больше четверти кусков из трёх букв, отвергается. Слово из пяти букв и
больше, набранное капителью, которое OCR прочитал в разных регистрах («INhIBITORS»), получает регистр большинства своих букв.

Страница, которую prep не считает сканом, но pymupdf4llm отправляет на OCR (текстовая страница с картинкой: схемой,
фотографией с подписями), читается один раз в режиме разреженного текста (`--psm 11`), без проверки поворота и
повторов, и результат сохраняется, только если он добавляет 8 слов, которых нет в текстовом слое (`convert_md`
передаёт `ocr_page.SCAN_PAGES` список сканов документа; повторы остаются для них). При планировании работы такая
страница стоит на секунду больше текстовой (`schedule.cost`, `image_pages` из prep); секунды OCR каждого файла
суммируются (`ocr_seconds`) и показываются в `intake status --json` и `intake_status`.

`intake_status` отвечает не более чем 3 000 символами: пакет (готово, в работе — со стадией, страницами и секундами
OCR, в ожидании, ошибки с причиной, оставшееся время), строка на каждое фоновое задание (завершённое — только если оно
закончилось после начала пакета: "Base recalculation: finished 8 h ago in 14 min, 82286 fragments, 113/s") и следующий
шаг; `intake_status(full=True)` добавляет `summary.md`, `intake_quality.md` и файлы без карточки. Известные
безобидные предупреждения библиотек моделей исключаются из хвостов вывода заданий (`HARMLESS` в `server/intake_tools.py`),
а пакет печатает строку прогресса при изменении или раз в 5 минут.

Страница обходится примерно в 2.5 с вместо 2 с со встроенным Tesseract (+0.5 с на проверку поворота); слабая — 6–15 с.
Для каждого документа, так что результаты остаются прежними (`tools\ocr_page.py`, проверено на эталонном корпусе байт в байт):

- **ориентация** проверяется на первых 5 страницах OCR (`OSD_SAMPLE`); если они согласуются, остальные страницы
  принимают её, и отдельно проверяется только страница, первое чтение которой слабое (однородный скан из 12 страниц:
  23.5 с → 20.3 с);
- **повтор**: после 10 слабых страниц вариант (400 dpi или чёрно-белый), выигравший на 70 % из них, становится
  единственным, который пробуется на следующих слабых страницах;
- **первое чтение сканированных страниц порции** выполняется одним процессом Tesseract (по списку изображений);
  страница, изображение которой отличается, читается отдельно. На этом ПК это экономит мало (дорог сам Tesseract, а не
  его запуск);
- `convert_md.py` держит один открытый PDF на документ и обрабатывает порциями по 50 текстовых страниц или по 5
  сканированных; PDF только из изображений страниц пропускает проверку скрытого текста (текста там нет вообще). В
  режиме `inproc` инструменты (hidden.py, assemble_md…) и так работают в рабочем процессе; `stage_mode = "subprocess"`
  сохраняет отдельный процесс на каждый инструмент.

Где видна оценка:

- уверенность и оценка каждой страницы — в `work\<DATE>\ocr\<tid>.json`;
- оценка документа — в `intake_quality.md`, в `meta_draft.jsonl` (`ocr_score`) и в `index\ocr_quality.tsv`
  (записывает `apply`);
- `assistant-x build` заносит её в `docs.ocr_score`; если она ниже 70, поиск указывает её в строке «Source quality».

Команды:

```
assistant-x intake ocr-score [CODE …] [--all] [--report file.md]
    score the library texts as they are (no OCR) → index\ocr_quality.tsv
assistant-x intake sample 20 [--seed S]
    random OCR pages (a third each of the worst, middle, good ones): PNG at 150 dpi, the library text
    and the new recognition side by side → debug\ocr_quality\sample
assistant-x intake redo CODE … | --worst N [--below 70] [--dry-run]
    recognize documents again (ocr_redo.py, work\redo\<date_time>); the text is replaced only when the
    vocabulary score grew by 10+ and the new text kept 80 % of the known words of the old one;
    every document is a row in intake_events.tsv, the report in reports\ocr_redo_*.md;
    after replacements — assistant-x build and assistant-x embed
```
## Журнал и события

`index\intake_events.tsv` — все события разбора (принят, дубликат, отклонён, к удалению, ошибка, в PDF, прогноз,
архив); `index\manifest.tsv` — достоверные сведения о файлах библиотеки (`manifest.py`). `journal.md` строит команда
`python -m assistant_x.core.journal` (`--check`, `--stats`): та же таблица, что и раньше, размер и хеш берутся из манифеста, если
в событии их нет, в конце — сверка с манифестом. Строки, добавленные в `journal.md` вручную,
переносятся в события модулем `core/journal.py` (`assistant_x.intake.journal` — тот же модуль). `assistant-x check` предупреждает, когда журнал отстаёт.

## Скрытый текст во всей библиотеке

`python -m assistant_x.intake.tools.hidden_scan` (в фоне: `pythonw`) — проход `hidden.py` по каждому PDF в `library` с
продолжением с места остановки; результат — `reports\hidden_text_<DATE>.tsv`, ход работы и итог (последняя строка
"DONE …") — в `.log` рядом с ним; `--status` — сколько проверено; `--new` — новый проход только по тем PDF, которых не
было в последнем завершённом (под блокировкой машины; `set AX_PRIORITY=idle` — только когда ПК свободен). После полного
прохода `--apply [--dry-run]` записывает `file.hidden_text` в карточки, а `assistant-x build` показывает его в строке
«Source quality». Новые документы проверяются при разборе (`prep`); сводка пакета показывает только фрагменты, похожие
на инструкции для ИИ (слово из suspect_words языковых пакетов: ignore, instruction, assistant, prompt, system и их
русские соответствия — во фразе, обращённой к ИИ, как её помечает поиск), остальные — только числом.

## Порядок работы (`schedule.py`)

После подготовки у каждого файла есть прогноз времени конвертации: текстовые страницы по 0.5 с и сканированные по
3.3 с (скорости первого реального пакета). Конвертации идут от самых дешёвых, так что небольшой файл никогда не ждёт
за большим сканом. Тяжёлая задача (прогноз от 15 мин, больше 800 страниц, файл, которому понадобился больший предел
памяти) выполняется рядом с другими тяжёлыми, пока их пределы памяти помещаются в 70 % свободной памяти сверх резерва
`balance.py`, измеряемой заново при каждом запуске; пока остаётся лёгкая работа, один рабочий процесс оставлен для неё.
Распознавание длинного скана режется на диапазоны страниц (не меньше 40 сканированных страниц в диапазоне, не больше
одного диапазона на рабочий процесс), которые пул выполняет как отдельные задачи; затем конвертация файла находит их в
кеше и собирает текст. `ocr_shards = "off"` отключает такую нарезку.

## Применение пакета разбора из Claude: план, токен, `auto_apply`

`intake_apply()` собирает карточки и возвращает план (что куда перемещается, какие шифры) с токеном подтверждения;
`intake_apply(confirm=True, token=…)` применяет его после согласия пользователя. Токен действителен 30 минут и только
один раз (`server/confirm.py`). Перенос выполняется в фоне одним заданием (`intake/apply_job.py`: build, apply, затем
пересчёт базы), и ответ приходит сразу ("The transfer started in the background: N documents…");
`intake_status` показывает стадию задания (`build`, `apply`, `build_index`, `embed`) и следующий шаг после него;
повторный вызов во время работы сообщает, что задание уже идёт. Сам план по-прежнему получается вызовом, который ждёт
завершения (build и `apply --dry-run`). `intake_reindex()` ничего не делает, когда база актуальна — нет фрагментов без
вектора, нет текстов или карточек новее базы, — и сообщает, когда она последний раз пересчитывалась (`reindex_last.json`
рядом с базой: начало, конец, фрагменты, векторы в секунду, устройство); `intake_reindex(force=True)` запускает
пересчёт в любом случае. Claude записывает строки `meta.jsonl` через `intake_save_meta(lines)` или пишет файл со строками
своими файловыми инструментами внутри папки пакета и передаёт `intake_save_meta(path=…)` (`meta.jsonl` самого
пакета проверяется как есть); `check_only=True` проверяет строки вместе с файлом и ничего не записывает.

`auto_apply = true` в `[intake]` файла `assistant_x.local.toml` (этот ПК, собственный выбор пользователя; никогда не
читается из `assistant_x.toml`, пакета базы или документа): пакет, проверка которого не находит ошибок, сразу
собирается, применяется и пересчитывается, а в ответе говорится "Applied automatically (auto_apply …)"; `changes.log`
отмечает вызов с `"auto": true`. План и токен остаются обязательными, с `auto_apply` или без, когда пакет
- заменяет документ библиотеки или является другой версией документа библиотеки (`replaces`, `other_version`),
- содержит дубликат документа библиотеки (`dupof` с шифром или вердикт разбора о дубликате),
- отклоняет файл (`drop`),
- содержит скрытый текст, обращённый к ИИ (скрытый текст файла со словами из `ai_phrases` или с названиями
  инструментов сервера).

## Изъятие документа из библиотеки

`assistant-x remove N-00268 [CODE …] [--why TEXT] [--dry-run]` (из Claude: `library_remove(codes, why)` — план
с токеном, затем `confirm=True` с этим токеном после согласия пользователя, выполняется в фоне) убирает в сторону
документы, попавшие в библиотеку по ошибке; ничего не удаляется. Для каждого шифра и для частей документа из
нескольких файлов: оригиналы из манифеста (и копия PDF), карточка и текст с `<code>.pages.json` и `<code>.hidden.json`
уходят в `inbox\_to_delete\removed_<code>_<date>\` с сохранением тех же папок; шифр исключается из `other_versions`
других карточек и из `ocr_quality.tsv`; `intake_events.tsv` получает по строке на файл, «removed: <why>» (`event_kind`
"removed": тот же файл, принесённый снова, не считается дубликатом); `manifest.tsv`, `journal.md`, `CATALOG.md` и
`sources_to_update.md` строятся заново; `index\codes.json` сохраняет номер зарезервированным; `build_index` удаляет
фрагменты и векторы документа (эмбеддинги не вычисляются); `changes.log` фиксирует изъятие. Журнал
(`index\remove.journal.json`) позволяет той же командой завершить прерванное изъятие.

## Личные документы

Документы, которые добавляет пользователь, по умолчанию попадают в ту же рабочую папку, на те же полки и в те же папки,
что и установленный пакет базы, как если бы пользователь наполнял его сам: `intake.personal` в их карточках — false,
отдельной полки для личных документов нет. Пополнение помечается только тогда, когда пользователь просит держать его
отдельно: `assistant-x intake build --personal` (для этого пакета разбора; MCP-команда `intake_apply(personal=True)`)
или `personal = true` в `[intake]` файла `assistant_x.toml` (для каждого пакета; `assistant-x init --personal`). Тогда
карточки получают `intake.personal: true`, а поиск помечает такой документ как «личный документ». Шифры в любом случае
выдаются одинаково — следующий свободный на полке: шифры общего пакета базы и документов пользователя согласуются при
добавлении пакета ([ROADMAP.md](../ROADMAP.ru.md), пункт 5), а не за счёт диапазонов номеров.
